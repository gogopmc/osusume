- 앱 이름: **트리니 링고**(띄어쓰기). 예전 이름은 "트리니티 오스스메".
  - 직원 전용 외국어 학습 앱이고, 약국 실제 상담 대화로 배웁니다.
  - 단어 → 문장 → 실전 대화 순서이고, 망각 주기에 맞춘 반복 복습이 핵심입니다.
- 주소: https://gogopmc.github.io/osusume (GitHub Pages)
  - 저장소: gogopmc/osusume (공개)
  - 기록 저장: Firebase 프로젝트 "trinity-osusume"의 Firestore `osusume` 컬렉션
- 로그인: 직원 이름 + 비밀번호 4자리.
- 언어: 일본어 15단원, 중국어 6단원, 영어 3단원.
  - 레벨과 경험치는 언어를 합산합니다.
  - 순위는 종합 순위 하나만 있습니다(1~3등 메달, 내 순위 표시).
- 사용자는 화면을 안 보고 음성으로 공부할 때가 많습니다. 키보드, 이어폰 버튼, 미디어키 조작이 중요합니다.
- 사용자는 이 앱을 고쳐서 다른 약국에 계정(구독)으로 파는 사업도 검토하고 있습니다.

## 2. 반드시 지킬 규칙 (사용자가 직접 말한 것)

### 작업 방식
- **사이트에 올리는 건 사용자가 채팅에서 "올려줘"라고 했을 때만** 합니다.
  - 음성 통화 중에는 올릴 수 없으니, 채팅으로 오라고 안내합니다.
- 새 언어는 사용자가 하자고 할 때만 추가합니다.
- 공지와 안내문에는 **이모지를 쓰지 않습니다**("AI 같아").
  - 공지는 짧게, 군더더기 없이 씁니다.
  - 단원 수나 "사다리" 같은 내부 용어는 공지에 넣지 않습니다.
- 앱 안의 글에는 직원 대화를 기록하거나 로그를 남긴다는 말을 쓰지 않습니다.
  - 대화문은 기밀 판매 노하우입니다.
  - 첫 화면에는 "직원 전용"이라는 안내를 둡니다.
- 부정행위 방지 장치는 당분간 만들지 않습니다.
- 중국어로 쓴 글에는 항상 한국어 번역을 같이 붙입니다.
- 힉스필드로 만들 때는 이미지는 GPT 이미지 모델(gpt_image_2_6), 영상은 시댄스(Seedance)를 씁니다.
- 폴더 구조는 2단계(상위 > 하위)를 싫어합니다. 폴더는 한 단계로만 만듭니다.
- 쓸데없는 말, 칭찬, 추임새 없이 간결하게 답합니다.

### 약국 정책 (대화문에 반영)
- **할인은 직원이 먼저 꺼내지 않습니다.** 손님이 물을 때만 안내합니다.
  - "물을 때만 안내해요" 같은 문구도 넣지 않습니다.
  - 5개를 사면 10% 할인입니다.
- 선물 포장은 해주지 않습니다. 대신 **예쁜 쇼핑백에 담아준다**고 합니다.
- 봉투(쇼핑백)는 **무료**이고, 계산할 때 필요한지 꼭 물어봅니다.
- 계산 순서: **여권을 먼저 찍고**(즉시 환급, 사후면세 아님) 그다음 손님 결제 바코드를 찍습니다.
- 중국 손님은 알리페이와 위챗페이를 많이 씁니다. 유니온페이 카드는 가끔 결제가 안 됩니다.
- **약국이 취급하지 않는 제품명은 쓰지 않습니다**(예: B5를 썼다가 지적받음). 대신 성분명을 씁니다.
  - PDRN 크림은 씁니다.
- 목염증약은 보통 **졸리지 않습니다**.
- 콜라겐은 포(파우치) 제품입니다. **하루 한 포, 포에서 바로 짜서** 먹습니다.
- 13단원 상황: 세트는 없고, 함께 사시면 할인해 드릴 수 있는지 허락받아 보겠다는 시나리오입니다.
- 약국에는 약사가 없고 한약사만 있습니다. 홍보물에 "약사"라는 단어를 쓰지 않습니다.

### 콘텐츠 원칙
- 단원 제목은 손님 말투로 씁니다(예: "여드름 자국이 남아요").
- 뒤쪽 단원일수록 난이도를 조금씩 올립니다.
- **앞으로 만들 단원의 순서 패턴**(모든 언어, 기존 단원은 그대로 둠):
  - 계산 용어 1단원 → 스킨케어 1~2단원 → 일반의약품(감기, 영양제 등) 1단원 → 스킨케어 2단원 정도…
  - 정확한 개수보다 이 흐름을 지키는 게 중요합니다.
- 영어는 다들 조금씩 하니까 **난이도를 높여서** 만듭니다.
  - 순서는 1단원 일반의약품(쉬움) → 2·3단원 스킨케어 → 4단원 계산("좀 비싸네요" 반응, 즉시 환급 등, 더 어려움)입니다.
  - 사용자가 1단원과 4단원을 바꾸자고 했습니다.
- 대화문을 먼저 쓰고, 그 직원 대사를 쪼개서 사다리를 만듭니다. 대화문 없이 사다리만 보여주지 않습니다.
- 대화문 표 형식은 `| | 영어 | 뜻 | 판매 노하우 |`이고, 손님 설정을 한 줄 붙입니다.
- 손님 사진은 현실적인 B급 사진입니다.
  - 앞쪽 단원 손님은 친절하고 예쁘게, 뒤로 갈수록 까다로운 손님을 섞습니다.
  - 병아리 마스코트는 귀엽게 둡니다.
- 일본어에 읽기(rd)가 있으면 음성은 읽기로 만듭니다(針 발음 문제를 이렇게 고침).
- 뜻(m)에는 한자나 괄호 설명을 넣지 않습니다. 한국어 음성이 한자를 "박"처럼 읽어버립니다.
- 뜻은 정답 판단이 쉽도록 원문 구조와 맞춥니다.
  - 예: のほうがいいです → "~쪽이 좋아요" ("~이 더 좋아요"로 쓰지 않음)
  - 사용자 말: "알아도 틀려서".

## 3. 사다리 학습 규칙 (지금은 영어만)

- 처음 배울 때: 표현 → 짧은 구 → 문장 → 긴 문장(대화 줄) 순서로 계단처럼 올라갑니다.
  - 아래 단계를 한 번 이상 맞혀야 위 단계가 열립니다.
- 새 단계는 새 단어나 표현이 더해질 때만 나눕니다.
  - ください, です처럼 끝맺는 말만 붙는 단계는 합칩니다(ニキビに塗って / ニキビに塗ってください를 쪼개지 않음).
  - 동사에 ください, ます, ました 같은 끝맺는 형태가 처음 붙을 때만 그 형태 단계를 동사 쪽에 넣습니다.
- **두 문장이 합쳐진 긴 문장은 항상** 앞 사다리와 뒤 사다리를 따로 만들고 꼭대기에서 합칩니다.
- 복습할 때:
  - 긴 문장(위 단계)부터 냅니다. 위 단계를 아는 동안에는 아래 단계를 내지 않습니다.
  - 틀리면 "어느 부분이 어려웠어요?"로 앞 / 뒤 / 다 어려워요 중에 고르게 합니다.
  - 고른 부분만 **3~5문제 뒤**에 내고(바로 내지 않음), 그 뒤에 긴 문장에 다시 도전합니다.
  - 아래 단계가 하나뿐이면 고르는 화면 없이 바로 그 단계를 냅니다.
- 사다리는 Claude가 적당히 만들고, 사용자가 써보면서 🚩 신고("기타" + 메모 "사다리 이상")로 고칩니다.
- **일본어와 중국어 적용은 12월 초**에 합니다. 11월 순위 상품이 걸려 있어서 미뤘습니다.
  - 적용할 때 기존 진도는 꼭 보존합니다. 기존 항목 id는 바꾸지 않고 새 단계만 추가합니다.
  - 단어와 문장을 둘 다 맞힌 적 있는 사람은 새 단계를 '이미 앎'으로 자동 처리합니다.
  - 안전장치: 일정 횟수가 지나면 막힌 문장을 열어줍니다(지금은 아래 단계를 3번 이상 틀리면 열림).

## 5. 기술 구조 (작업자용)

### 원본과 빌드
- 원본은 저장소의 `src/` 폴더입니다. 사이트 파일은 루트의 `index.html` 하나입니다.
- `src/web.tpl.html`이 앱 템플릿입니다. 버전은 `APP_VER`(지금 "v43")입니다.
  - 빌드할 때 `__CONTENT__`, `__CLIPS__`, `__AUD__`를 바꿔 넣습니다.
- 콘텐츠 파일:
  - 일본어: `content.js`(1단원, WORDS/SENTS/DIALOG), `units23.js`, `units47.js`, `units89.js`, `units1012.js`, `units1315.js` (`window.__EXTRA_UNITS`)
  - 중국어: `units_zh.js`(`window.__UNITS_ZH`), `units_zh2.js`(push)
  - 영어: `units_en.js`(`window.__UNITS_EN`)
  - 항목 형식: `{id,g,ja,rd,p,m,parts,tip,dn}`
    - ja = 원문(언어와 상관없이 필드 이름은 ja)
    - rd = 읽기(히라가나나 병음), p = 한글 발음(영어는 없음), m = 뜻
    - dn = 사다리 바로 아래 단계 id 목록(영어만)
  - 대화 D의 r 값: "c"는 손님, "s"는 직원.
- 빌드: `src` 폴더에서 `python3 build.py`를 실행합니다.
  - 루트 `index.html`을 다시 만들고, 새 음성 줄을 `tts/list.tsv`에 추가하고, `audmap.json`을 갱신합니다.
  - **빌드한 index.html을 커밋하고 푸시하면 바로 사이트에 반영되므로, "올려줘" 전에는 index.html을 커밋하지 않습니다.**
- 커밋은 Claude 이름으로 하고, 끝에 Co-Authored-By와 Claude-Session 줄을 붙입니다.

### 언어 처리
- LANG은 localStorage의 "trini-lang" 값입니다(ja, zh, en).
- 항목 id 접두어: 일본어는 1단원이 없음, 나머지는 "u2-"처럼. 중국어는 "zu1-", 영어는 "eu1-".
- 단원 키 UK: 일본어는 그대로, 중국어는 z, 영어는 e.
- 손님 사진: 일본어 `img/c1~c15.jpg`, 중국어 `img/z1~z6.jpg`, 영어 `img/e1~e3.jpg`.

### 음성
- GitHub Action `azure-tts`가 `tts/*.tsv`로 음성을 만듭니다. secret은 AZURE_SPEECH_KEY, 지역은 koreacentral, F0 요금제입니다.
- 목소리와 속도:
  - 일본어: ja-JP-MayuNeural, 0%
  - 한국어: ko-KR-SunHiNeural, +12%
  - 중국어: zh-CN-XiaoxiaoNeural, 0%
  - 영어: en-US-JennyNeural, 0% (사용자가 샘플 중 1번을 고름)
- 음성 id는 `md5(언어+목소리+속도+'|'+읽을 글)` 앞 12자리입니다. `audmap.json`이 글과 id를 이어줍니다.

### 사진
- 사진은 `img/list.txt`에 "이름 힉스필드id"로 적으면 `fetch-images` Action이 받아옵니다.
- 작업 공간에서는 cloudfront에 직접 접근할 수 없어서 이렇게 합니다.

### 데이터
- Firestore 읽기와 쓰기는 작업 공간에서 막혀 있어서, 힉스필드 sandbox_exec(인터넷 가능)에서 REST로 합니다.
- 문서:
  - 진도: `osu-p-<이름키>`
  - 학습 로그: `osu-log-<이름키>-<날짜>`
  - 신고: `osu-rep-<시각>-<이름키>`
  - 프로필: `osu-profiles`
- 이름키는 글자마다 코드포인트를 36진수로 바꿔 이은 것입니다. 민철 = `114s14f4`.

### 테스트와 스케줄러
- 테스트는 `src/test-*.js`(Playwright)입니다.
  - test-lad2.js: 사다리 위반 검사
  - test-zh.js: 중국어 음성 누락 검사
  - test-cv.js: 대화 중 화면 넘김 검사
  - test-fb.js: 로딩
- 스케줄러 핵심:
  - 처음 배운 항목은 2문제 뒤와 7문제 뒤에 리마인드합니다(LADDER).
  - 맞으면 ×6, 틀리면 ×0.5, 이미 알아요는 한 달 뒤입니다.
  - 틀린 문제는 몇 문제 뒤 다시 냅니다(retryQ). 한 세션에 4번 틀리면 12시간 쉽니다.
